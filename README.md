# 💜 Наше пространство — планировщик жизни для пары

Совместный планировщик задач, календаря, целей, покупок и т.д. для двоих.
React + TypeScript + Vite + Tailwind CSS + Firebase (Auth + Firestore) + FullCalendar + Zustand.

Реализовано: задачи (с чек-листами, приоритетом, категориями, назначением "Я/Партнёр/Вместе"),
календарь с drag&drop, общие цели с прогрессом, список покупок, дашборд (сегодня/ближайшее/просрочено/погода),
тёмная/светлая тема, приглашение партнёра по коду, реалтайм-синхронизация через Firestore.

---

## 1. Что вам понадобится

- [Node.js](https://nodejs.org) версии 18+ (для запуска проекта локально)
- Бесплатный аккаунт Google для Firebase
- Аккаунт GitHub (чтобы сохранить код и при желании поделиться репозиторием)

Всё, включая хостинг, у Firebase бесплатно на объёме, которого с запасом хватит для двоих пользователей (план Spark).

---

## 2. Создание Firebase-проекта (~5 минут)

1. Зайдите на [console.firebase.google.com](https://console.firebase.google.com) и нажмите **"Add project" / "Создать проект"**.
2. Назовите проект (например, `our-life-planner`), Google Analytics можно отключить — он не нужен.
3. Когда проект создан, в боковом меню откройте **Build → Authentication**, нажмите **Get started**,
   включите провайдер **Email/Password**.
4. Откройте **Build → Firestore Database → Create database**. Выберите режим **Production mode**
   и любой ближайший регион (например, `eur3` для Европы).
5. Откройте **Project settings** (шестерёнка сверху слева) → вкладка **General** → в самом низу
   раздел **"Your apps"** → нажмите иконку **`</>`** (Web app), задайте имя (например, `web`),
   галочку "Firebase Hosting" можно не ставить сейчас — настроим отдельно ниже.
6. Firebase покажет объект `firebaseConfig` — скопируйте значения `apiKey`, `authDomain`,
   `projectId`, `storageBucket`, `messagingSenderId`, `appId`.

---

## 3. Настройка проекта локально

```bash
# Установить зависимости
npm install

# Скопировать пример .env и вставить туда значения из firebaseConfig
cp .env.example .env
```

Откройте `.env` и заполните:

```
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=...
VITE_FIREBASE_PROJECT_ID=...
VITE_FIREBASE_STORAGE_BUCKET=...
VITE_FIREBASE_MESSAGING_SENDER_ID=...
VITE_FIREBASE_APP_ID=...
```

Запустите локально, чтобы проверить, что всё работает:

```bash
npm run dev
```

Откройте `http://localhost:5173`, зарегистрируйтесь, создайте пространство —
приложение должно сохранять данные в Firestore (вы увидите документы в консоли Firebase → Firestore Database).

**Важно:** файл `.env` содержит ваши ключи и уже добавлен в `.gitignore` — он не попадёт в GitHub.
Это нормально: ключи Firebase для веб-приложений не секретны сами по себе (защиту обеспечивают
правила безопасности Firestore, которые уже настроены в `firestore.rules`), но так чище.

## 4. Загрузка правил безопасности Firestore

Правила уже лежат в файле `firestore.rules` — они гарантируют, что видеть и редактировать
задачи, цели и покупки может только владелец пространства и его партнёр. Загрузить их можно так:

```bash
npx firebase-tools login       # один раз — откроется браузер для входа в Google-аккаунт
npx firebase-tools use --add   # выберите ваш проект и присвойте алиас, например "default"
npm run deploy:rules
```

## 6. Деплой на Firebase Hosting (получаете ссылку для двоих)

```bash
npm run deploy
```

Эта команда сама соберёт проект (`npm run build`) и опубликует папку `dist` на Firebase Hosting.
В конце в терминале появится строка вида:

```
Hosting URL: https://ваш-проект.web.app
```

Это и есть ссылка, которую можно отправить девушке. Она открывает её, регистрируется
(**Регистрация** → email + пароль), а дальше на экране **"Есть код"** вводит код приглашения,
который вы увидите у себя в **Настройках** после создания своего пространства (или сразу
после регистрации на экране создания пространства). После этого вы оба работаете в одном
общем пространстве, и все изменения синхронизируются мгновенно.

Если что-то поменяете в коде — просто снова выполните `npm run deploy`, чтобы обновить сайт.

## 6.1. Автоматический деплой при каждом пуше (без WebStorm)

Если не хочется каждый раз запускать `npm run deploy` вручную — можно настроить это один раз,
и дальше сайт будет сам обновляться при каждом `git push` в GitHub (через GitHub Actions).
Файл `.github/workflows/deploy.yml` уже готов, нужно только один раз добавить секреты.

**Шаг 1 — создать сервисный аккаунт Firebase:**
1. [console.firebase.google.com](https://console.firebase.google.com) → ваш проект → шестерёнка ⚙️ → **Project settings**
2. Вкладка **Service accounts** → кнопка **Generate new private key** → скачается файл `.json`
3. Откройте этот файл текстовым редактором, скопируйте всё содержимое

**Шаг 2 — добавить секреты в GitHub:**
Откройте `https://github.com/IgorAfanasyevv/Calendar/settings/secrets/actions` → **New repository secret**
и добавьте по очереди (имя secret → значение):

| Имя секрета | Значение |
|---|---|
| `FIREBASE_SERVICE_ACCOUNT` | всё содержимое скачанного `.json`-файла целиком |
| `VITE_FIREBASE_API_KEY` | из вашего `.env` |
| `VITE_FIREBASE_AUTH_DOMAIN` | из вашего `.env` |
| `VITE_FIREBASE_PROJECT_ID` | из вашего `.env` |
| `VITE_FIREBASE_STORAGE_BUCKET` | из вашего `.env` |
| `VITE_FIREBASE_MESSAGING_SENDER_ID` | из вашего `.env` |
| `VITE_FIREBASE_APP_ID` | из вашего `.env` |

**Готово.** После этого при каждом `git push` в ветку `main` GitHub сам:
1. установит зависимости,
2. соберёт проект,
3. опубликует сайт на Firebase Hosting,
4. обновит правила безопасности Firestore.

Прогресс можно посмотреть на вкладке **Actions** в GitHub-репозитории. Регистрировать
новые аккаунты/пользователей это не требует — это отдельный процесс: настройка CI/CD один раз
делает так, чтобы *сам код* публиковался автоматически, а регистрация пользователей в приложении
как работала через экран входа, так и работает.

## 7. Структура проекта

```
src/
  lib/firebase.ts         — инициализация Firebase
  types/index.ts           — типы данных (Task, Goal, ShoppingItem, Workspace...)
  store/                   — Zustand-сторы (auth, workspace, tasks, goals, shopping, theme)
  components/               — переиспользуемые компоненты (Layout, TaskModal, Calendar, Modal...)
  pages/                    — экраны (Auth, WorkspaceSetup, Home, Goals, Shopping, Settings)
firestore.rules             — правила безопасности Firestore
firebase.json                — конфигурация Hosting/Firestore
```

## 8. Что можно добавить дальше

Изначальный список пожеланий был очень большим — в этой версии сделан рабочий MVP с ядром
функций (задачи, календарь, цели, покупки, дашборд, тема, общий доступ). За рамками остались:
push-уведомления, финансовый раздел с диаграммами, дневник отношений, привычки со streak,
важные даты/годовщины, офлайн-режим, экспорт/импорт, история изменений. Структура проекта
(отдельные Zustand-сторы + Firestore-коллекции на каждый раздел) сделана так, чтобы такие
разделы было легко добавлять по той же схеме, что уже есть у целей и покупок.
